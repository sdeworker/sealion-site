# 海狮官网页头品牌与导航自适应设计

日期：2026-08-01

范围：中文、英文、俄文全站公共页头

基线：`main` 提交 `5d40010`（已加入导航文字不换行，并在 1560px 以下隐藏口号）

## 1. 问题与证据

用户截图中，品牌标志未按原比例完整显示，中文栏目在可用宽度不足时被挤成两行。

本地读取当前生产源码并测量三语首页后，确认问题不是标志图片文件缺失，而是页头布局在 Flex 收缩时压缩了品牌区：

- 全站正文容器最大宽度是 1440px，页头也共用这一限制；宽屏中页头无法利用屏幕两侧空间。
- `.brand` 默认允许 `flex-shrink: 1`，全局 `img { max-width: 100% }` 会随父级一起压窄图片，但 `.brand img` 的高度仍固定为 72px，最终造成横向变形。
- 1920px 视口下，标志自然宽高比应为 `611 / 203 = 3.010`；中文页实际为 2.848，英文页实际为 2.209，英文页失真最明显。
- 当前提交已经给导航文字加上 `white-space: nowrap`，解决了文字换行的表象；但宽度不足时会继续压缩品牌区。
- 当前汉堡菜单只在 1024px 以下启用。中文完整导航约 907px，加上正常比例标志、间距和容器边距后，约在 1320px 以下开始缺少安全余量。

## 2. 设计目标

1. 标志始终保持原始宽高比，不裁切、不压扁，也不靠减小字号换空间。
2. 桌面导航的一级栏目始终单行显示。
3. 宽度不足时按“先隐藏口号，再切换汉堡菜单”的顺序降级。
4. 中文、英文、俄文采用同一套稳定规则，不为单页写临时补丁。
5. 不改变页头高度、栏目名称、导航结构、移动菜单交互和首页 Hero 的定位关系。

## 3. 采用的布局方案

### 3.1 页头使用独立宽容器

保留正文 `.wrap` 的 1440px 阅读宽度，只给 `.site-header .bar` 设置 1760px 最大宽度。这样不会放宽正文段落和产品内容，只让品牌、口号、导航充分利用宽屏空间。

### 3.2 固定品牌与导航的收缩行为

- `.brand` 使用 `flex: 0 0 auto`，去掉依赖收缩的布局行为。
- `.brand img` 保持 `height: 72px; width: auto; max-width: none`，确保宽高比恒定。
- `.nav` 使用 `flex: 0 0 auto; margin-left: auto`，导航整体靠右且不参与压缩。
- `.slogan` 不参与压缩；它只在空间充足时显示。
- 一级导航链接和语言按钮保持 `white-space: nowrap`。远端最新提交中已有的有效规则予以保留。

### 3.3 响应式分级

- 大于 1560px：显示标志、口号和完整导航。
- 1321px–1560px：隐藏口号，显示标志和完整导航。
- 1320px 及以下：隐藏桌面导航，显示现有汉堡菜单。
- 760px 及以下：沿用现有顶部欢迎语隐藏等手机规则。

1320px 断点按中文导航的实际几何宽度确定；中文是三种语言中当前一级导航最宽的一组。该断点也能覆盖 1920px 屏幕在 150% 缩放时约 1280px 的 CSS 视口。

## 4. 实现范围

主要修改 `public/style.css` 中公共页头规则；如该仓库要求生成文件与源模板同步，则同时修改对应源文件并运行现有生成脚本。新增自动化回归测试，验证关键 CSS 约束和页面几何。

本次不做以下事项：

- 不再次编辑 `public/assets/logo.png`，避免继续累积透明边距或图片加工误差。
- 不缩小当前 1.25rem 的一级导航字号。
- 不修改中文、英文、俄文栏目文案和链接。
- 不重做下拉菜单、顶部热线、Hero 或移动菜单交互。
- 不调整正文容器宽度和其他页面版式。

## 5. 验收标准

### 5.1 自动化约束

- 品牌容器和导航容器不得收缩。
- 标志高度保持 72px，显示宽高比与源图片比值 3.010 的误差不超过 0.01。
- 桌面状态下，一级栏目高度一致且不出现换行。
- 1320px 及以下显示汉堡菜单、隐藏桌面导航；1321px 以上反之。
- 1560px 及以下隐藏口号；1561px 以上显示口号。

### 5.2 视觉回归矩阵

分别检查中文 `/`、英文 `/en/`、俄文 `/ru/`：

- 1920×1080：标志、口号、完整导航全部正常。
- 1536×864：口号隐藏，标志与完整导航正常。
- 1440×900：口号隐藏，完整导航单行，标志不变形。
- 1280×800：汉堡菜单启用，标志不变形。
- 手机宽度 390×844：现有移动菜单和顶部信息条行为不退化。

同时检查首页透明页头与滚动后的实底页头，确认颜色、下拉菜单和 Hero 顶部偏移没有变化。

## 6. 风险与回滚

风险集中在断点从 1024px 提前到 1320px：部分小尺寸笔记本会更早看到汉堡菜单。这是有意取舍，优先保证品牌完整和栏目可读。

改动仅涉及公共 CSS 和测试，回滚时恢复本次提交即可；不涉及内容数据、图片替换或页面结构迁移。
